# Documento histórico de 0.3.0

El estado actual y las decisiones de esta entrega están en DECISIONS_0.3.1.md y ESTADO_ENTREGA.md.

# Decisiones · Fases 1A y 1B

1. **Entrega local por fases.** Se implementan 1A y 1B del documento proporcionado. Los módulos de planificación y control están activos. Se conserva el alcance local, sin publicar datos ni conectar Supabase o GitHub real.
2. **Next.js App Router + TypeScript estricto + Tailwind 4.** Las versiones resueltas están en pnpm-lock.yaml. El CSS propio define el diseño responsive, sin depender de fuentes remotas. Iconos: lucide-react. La estética se adaptó a la referencia MEC402 indicada posteriormente por el usuario (ver DESIGN.md). Poppins se distribuye localmente con su licencia SIL OFL.
3. **SQLite integrado en Node 24.** Drizzle 0.45 utiliza sqlite-proxy para consultar el driver nativo node:sqlite. Evita compilar módulos nativos y utilizar la versión RC de Drizzle necesaria para su adaptador node-sqlite. Los repositorios aíslan el almacenamiento.
4. **Agregados por proyecto.** Usuarios y sesiones son tablas separadas; equipos, actividades, membresías, comentarios y auditoría se guardan en un documento JSON validado por Zod dentro de cada fila de projects. Es una decisión para la primera versión local, de un solo proceso. Antes de Supabase se deben normalizar las entidades y sustituir la cola de escrituras por transacciones. No se afirma que esto sea el esquema relacional completo de las cuatro fases.
5. **Demostración explícita.** El botón Explorar inicia una sesión de administrador limitada a los dos proyectos de ejemplo. No existe superusuario con contraseña predeterminada. Las contraseñas de las nueve cuentas de muestra son aleatorias y se descartan. El acceso demo es exclusivamente para esta entrega local; debe eliminarse o aislarse antes de alojar proyectos reales.
6. **RACI.** A es un único identificador y R una lista. Se permite guardar una actividad incompleta, pero la lista y su editor avisan si falta A o R. Los identificadores asignados se validan contra la membresía del proyecto.
7. **Días y dinero.** Fechas de planificación son ISO YYYY-MM-DD; los instantes del historial son ISO UTC y la fecha actual usa America/Guatemala. CPM usa duración entera hábil y desfase FS; un administrador aplica el cronograma después de ver el impacto. El presupuesto suma cantidades enteras y precios en centavos, con aprobación separada de gastos.
8. **Seguridad local.** bcrypt a 12 rondas en cuentas reales, cookies httpOnly y sameSite=strict, secure en producción, tokens de sesión y recuperación guardados con SHA-256, token de recuperación de 30 minutos y bloqueo de 8 intentos por correo durante 15 minutos. Se compara Origin con Host para cada escritura. Las entradas tienen límites Zod y la UI muestra texto mediante React.
9. **Concurrencia.** Las escrituras HTTP se serializan en un proceso Node para evitar sobrescribir un agregado durante las operaciones await. No admite múltiples procesos escritores; el despliegue horizontal requiere transacciones y otra estrategia.
10. **Alcance de filtros.** Estado, completadas/no completadas, equipo, persona, RACI, prioridad, vencidas/bloqueadas/próximas, semana, fechas, texto y presencia de commits simulados se guardan en la URL. El filtro de crítica y las dependencias están conectados al CPM en 1B. No se simula una integración GitHub real.
11. **Edición de actividades.** El panel de detalle permite editar todos los campos implementados, RACI y jerarquía WBS. La lista ofrece edición de nombre en línea y cambio rápido de estado; el Kanban permite arrastrar actividades con permisos. Los controles de 1B se implementan en PhasePanel y PlanningGantt, con las mismas comprobaciones de permisos en el servidor.
12. **Compilación local.** `npm run build` usa `next build --webpack`. Turbopack falló en el intercambio con su proceso de PostCSS en este entorno; el mecanismo alternativo documentado por Next.js completó la compilación. El modo de desarrollo conserva Turbopack. Referencia: https://nextjs.org/docs/app/guides/upgrading/version-16.

Referencias de implementación verificadas: [Next.js Route Handlers](https://nextjs.org/docs/app/api-reference/file-conventions/route), [cookies](https://nextjs.org/docs/app/api-reference/functions/cookies), [Drizzle SQLite](https://orm.drizzle.team/docs/sqlite/get-started-sqlite). También se consultó la documentación incluida en node_modules/next/dist/docs.

13. **Importación sin inventar datos.** Se conservan 11 hojas de la matriz y el XLSX privado. Las 25 actividades mantienen RACI de equipo y asignaciones personales iniciales editables. Duraciones/fechas ausentes son provisionales; precios y mediciones permanecen pendientes.
14. **Evaluaciones independientes.** Programación recibe administración global, pero la bandera docente controla las evaluaciones antes de aplicar el privilegio global. Las notas se almacenan separadas del proyecto y no se exportan a alumnos. No se permite que un administrador estudiante restablezca o modifique el acceso del docente.
15. **Archivos privados.** Se valida extensión, firma o contenido y tamaño, se usa un identificador aleatorio para el almacenamiento y se exige permiso de proyecto en cada descarga. Los respaldos conservan adjuntos y se restauran como proyectos nuevos tras validar jerarquía y dependencias.
